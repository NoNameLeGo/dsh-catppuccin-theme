# 可读性全量实测（2026-11-07，issue #39 之后）

目的：确认 #39 修完后，皮肤是否还在别处制造「看不清」。**只测，不改代码**（本文件记录的判断等维护者定）。
环境：官方桌面壳 `0.2.2-rc.1`、插件 `0.7.2`、Windows 11、1280×822（dpr 1.5）。

## 方法

不用「计算样式合成」推算背景（JS 里近似 `backdrop-filter` 与多层 alpha 会失真），而是**取真实像素**：

1. `Page.captureScreenshot` 整屏，Node 内置 `zlib` 解 PNG（无第三方依赖）；
2. 对每个「自己带文本」的元素取包围盒内的像素直方图，**众数色 = 该元素实际渲染背景**；
3. 文字取计算样式里的声明色（`color`，含 alpha 就按背景合成），算 WCAG 对比度。

脚本：`.debug/issue-39/deep-audit.mjs`（文本）、`icon-audit.mjs`（图标，用「声明色 vs 局部众数背景」，
并跳过被遮挡的 svg）；驱动 `run-matrix.sh`。检测器自检：注入已知 1.04:1 的探针能被抓到。

> 已知局限：只覆盖**可见视口内**、且「元素自己带文本」的节点（子 span 单独计）；图标另测；
> 不判「文字叠文字」这类分层问题；macOS/Linux 壳未测。

## 覆盖

4 风味 × 云母（Latte / Frappé / Macchiato / Mocha）+ Latte/Mocha × 兼容，每态 4 个界面：
转录页、设置对话框（作用域 `[role='presentation'] [role='dialog']`，排除被压暗的背景层）、
模型选择弹层、账号菜单。共 **24 组截图 + 报告**，每组 22–111 个文本节点。

另测极端滑条：frost 0 / 100、brightness 100（Latte）/ 0（Mocha）、光斑 200% 强度 × 250% 尺寸。
另用 `sweep-tooltips.mjs` 逐按钮悬停采 tooltip：四风味各 10 条。

## 结果

**没有任何一处文本低于 3.0:1**，唯一的两项：

| 项 | 值 | 判定 |
|---|---|---|
| 发送按钮图标（禁用态，`opacity: .4`） | 2.06:1 | 宿主禁用样式，玻璃开/关一致，不算缺陷 |
| 菜单快捷键提示 `Ctrl`（Latte + 兼容，鼠标停在首项时的 hover 底） | 2.9:1 | 见下，**玻璃相关** |

tooltip 四风味最低对比度：Latte 7.06 / Frappé 6.19 / Macchiato 7.55 / Mocha 8.69，均远超 AA。
图标（按 WCAG 非文本 3:1 判）：Latte 云母 46 个 svg 里最低 2.06（**禁用态**发送键），
除它之外是 composer dock 的三个 **3.25 / 3.35 / 3.66**（选择模型、访问模式、上下文用量），仍在 3:1 线以上；
Mocha 最低 5.03；兼容模式最低 1.95（同一个禁用发送键）；设置对话框内 14 个最低 4.48。
同元素 A/B：图标最大跌幅 −1.72（5.38 → 3.66），未跌破 3:1。
极端滑条（frost 0/100、亮度两端、光斑最大）都未把任何文本压到 3.0 以下。

### 玻璃真的压低了什么（同元素 A/B，2026-11-07 更正）

> ⚠️ **本节推翻了本文初版的结论**。初版把「玻璃开」和「玻璃关」两次独立截图按
> `选择器 + 文本` 配对，结果页面上有两个 `Ctrl`（侧栏「新会话」的、账号菜单里的）被混成一条，
> 得出「菜单 `Ctrl` 5.53 → 3.38」——那是**两个不同元素**的比值，不成立。
>
> 现在的做法：先把每个带文本的元素打上 `data-leg-id`，再在同一页面里切玻璃开/关各量一次，
> **按 id 配对**，布局位移不会污染结果（脚本 `.debug/issue-39/compare.mjs`）。

Latte + 云母 + frost 20，转录页 111 个配对元素：

| 元素 | 玻璃关 | 玻璃开 | Δ |
|---|---|---|---|
| 轨迹页签「轨迹」13px | 5.53:1 | **4.23:1** | −1.30 |
| 轨迹页签「对话」13px | 4.34:1 | **3.59:1** | −0.75 |
| 「已搜索代码」12px | 5.53:1 | 5.01:1 | −0.52 |
| 状态栏三项（轮/步、token、上下文） | 5.38:1 | 4.87:1 | −0.51 |
| 「Design 模式」13px | 6.28:1 | 5.97:1 | −0.31 |

**没有一处掉到 3.0 以下**；最大跌幅 −1.30，且最低值 3.59 的那一项在玻璃关时也只有 4.34
（宿主自己的 `caption` / `secondary` 级配对，本来就低于 AA）。按规则 1「拿不出『官方取值在 DSH 下不成立』
的证据就不偏离」，这些不动。跌幅本身来自面板填充（frost 20 ⇒ 面板 10.4%），是滑条的正常作用域。

### 曾提议的「弹层填充下限」：实测无收益，已撤销

初版建议给菜单加 `max(58%, 64% × frost)` 的下限。真机复核：

- 菜单里的 `Ctrl`：无下限 3.19 → 有下限 3.14（**没有改善**）；
- 菜单项文字两侧都在 6.4 左右，几乎不动。

原因很简单：**Latte 下 `bg-layer-1` 就等于 `bg-base`**，弹层填充从 25.6% 提到 58% 只是把同一颜色
叠得更实，合成结果几乎不变；深色风味那边文字是浅色、越实越清楚，本来也不会低于线。
所以这个改动没有对应任何实测缺陷，**已回退**，不留无证据的材料改动。

残留观察（不属于缺陷，未改）：轨迹页签这类「宿主自绘小字压在玻璃面板上」的组合，
在 frost 很低（20 及以下）时会比宿主原样低 0.3–1.3 个对比度层级；要改善只能加面板填充或改配色，
前者与「要透」的取向冲突，后者违反规则 1，都需要单独决策。

## 本轮自检发现的口径问题（2026-11-07 晚）

复查上面这些数字时又抓出三处，全部只涉及**表述/工具**，不影响任何代码：

1. **跨截图的 A/B 不能按「选择器 + 文本」配对**（初版就栽在这里，见上节更正）。
   正确做法是给元素打 `data-leg-id` 后同页配对；副作用是：若 React 在两次快照之间重建了节点，
   带 id 的元素会消失 → 该元素被排除出配对（偏向稳定的标签类元素，对本议题无害，但要知道）。
2. **`sweep-tooltips.mjs` 把页面底色写死成 Latte 的 `rgb(239,241,245)`**，只对**不透明** tooltip 无害。
   本轮 40 条采样全部是不透明底（α = 1.00），重算后数字不变；但将来若出现半透明 tooltip（如轮次预览那种）
   就会算错，用前必须换成按当前风味取 `--dsw-alias-bg-base`。
3. **「包围盒众数色 = 背景」在小框里会失真**：字形占比高的 10–14px 框（快捷键、图标）众数可能取到字形色。
   表现是「假阳性」（报出 1.x:1 的不可见文字）而非漏报，本轮已被 3.0 阈值和其它读数交叉验证排除；
   仍未覆盖的是「文字叠文字」这类分层问题，只能靠目视截图。
4. 一处措辞过精：issue #39 的「修复前 1.00:1」是**纯色底**上的值（文字与合成背景同为 `#eff1f5`）；
   实际压在转录文字上时会略高（≈1.0–1.1）。对结论无影响，回帖与 CHANGELOG 已发，不再改写历史条目。

## 二轮复测（2026-11-07 14:0x，估计器换成「自身填充叠在框外表面」）

首轮的两个估计器各有硬伤：**框内众数**在紧贴字形的框里会被字形色带偏（假阳性），**只量框外环带**
对自带不透明底的元素会读到它背后的页面（假阴性，探针复测时漏掉了 1.04:1）。二轮改成：

```
背景 = 元素自身 background-color（含 alpha）叠在「框外 3px 环带的众数色」上
```

环带给真实的外层像素，自身填充给压在上面的那层。探针自检恢复有效（1.04:1 能抓出）。
同一元素仍按 `data-leg-id` 配对做玻璃开/关 A/B。

**覆盖**：6 配置 × 4 界面（转录 / 设置对话框 / 模型弹层 / 账号菜单）= 24 次，
Latte 追加 3 个界面（插件页 / 上下文洞察 / 搜索）= 27 次；另有 Latte 转录页、上下文洞察、设置对话框
三处逐元素 A/B，以及图标的 A/B（`compare.mjs --icons`）。

**结果：没有一处是玻璃造成的「看不清」。** 全部低于 3:1 的读数只有三类，且都与玻璃无关或只差 ±0.2：

| 读数 | 位置 | 玻璃关 | 判定 |
|---|---|---|---|
| 2.83–3.38 | 账号菜单里悬停行上的 `Ctrl` 快捷键（11px caption 色） | 3.16 | 宿主自己的 caption × hover 底色，玻璃至多 −0.2；Frappé 同样（2.75–4.10 / 关玻璃 2.92） |
| 2.64 | 第三方插件「上下文洞察」的橙色 `↑ v0.82.1` 徽标 | 2.64 | **完全不受玻璃影响**（delta 0），是该插件自己写死的橙色 |
| 2.88–2.91 | 设置对话框打开时**背后被压暗**的侧栏时间戳/分组标题 | 同值 | 模态遮罩使然，不是可读内容 |

玻璃自身造成的最大跌幅仍是：图标 −1.72（5.38→3.66，非文本 3:1 线以上）、页签的字 −1.30（5.53→4.23），
全程没有一处文本跌破 3.0、没有一处图标跌破 3:1（禁用态除外，WCAG 豁免）。

**一条观感观察（不是缺陷）**：frost 20 时设置对话框/弹层的填充只有 25.6%，背后的转录能被读出来
（实测 3.9–4.2:1），两层文字互相干扰；frost ≥ 45（默认 50）时填充回到 ≥58%，bleed-through 消失。
这是旋钮的取值范围问题，不是肤色或材质错误。
