# 框语言审计：七个「框」对不上的地方（2026-10-19）

- 触发：维护者 2026-10-19 真机截图提问「当前插件有哪些框是不统一、或你觉得需要改的」。
- 状态：**只审计，一行代码未改**。证据等级见 §1.1：**① ② ③ ⑦ 已逐条对过源码**（含生成的
  `GLASS_CSS_TEXT` 与 `glass-seams.ts` 的接缝选择器）；**④ ⑤ ⑥ 只有截图取证**——它们的成因不在本表
  （上游布局 / 上游自绘控件 / 列高与外壳），改之前必须先取 DOM 或 computed style。全部等维护者点编号
  （③ 还会牵动 `docs/issue-28-fused-composer-plan.md`）。
- 取证环境：官方桌面壳 `0.2.1-rc.2`，Mocha + mica（float），Windows 标题栏在位，截屏 2560×1528，
  设备像素 / CSS px ≈ 1.5（由侧栏列宽 279 CSS ≈ 上游默认 280 与顶栏 margin 16 双向校准）。
- 取证方法：逐行扫像素取**描边峰值 RGB** 与圆弧轨迹拟合，再对 CSS 逐条核对。出图
  `.debug/frame-audit/AUDIT_annotated.png`（**不入库**，同目录另有 8 张裁切件）。描边亮度可直接横向比：
  同一 Mocha 地面 `rgb(16,16,26)` 上，alpha 越高峰值越亮。

## 1. 现在的框长什么样

**alpha 有两个口径，别混**（这条 2026-10-19 复核时更正过）：三档 rim 在**浅色**分支是
18 / 12 / 30%（`glass.module.css` 57–59 行），在**暗色**分支是 **24 / 16 / 30%**（111–117 行）——
暗地面上同 alpha 读起来更弱，所以整体抬了一档。下表「rim」列按 `暗 / 浅` 写（截图是 Mocha，取暗色那档）。

| 面 | 圆角 | rim（暗 / 浅） | 峰值 RGB（Mocha） | 投影 | 出处 |
|---|---|---|---|---|---|
| 会话顶栏 | 20 | 24 / 18% | `(65,67,82)` | edge + drop | 759–767 |
| 侧栏卡 | 20 | **16 / 12% soft** | `(51,52,67)` | **只 drop，无 edge** | 799–828（#26 软化） |
| 轨迹面板 | 20 | 24 / 18% | —（本图未开） | edge + drop | 926–935 |
| 输入卡 | **24** | **30 / 30% strong** | `(74,77,93)` | input-shadow 双层 | 973–995（#22 加强） |
| 消息气泡 | 14 | 16 / 12% soft | `(47,49,64)` | 无 | 436–451 |
| 菜单（MenuSurface） | 14 | **0（撤了）** | — | 上游自己的 | 1104–1107（#22 ③） |
| 对话框 | 14 | 24 / 18% | —（本图未开） | **只有 edge，无 drop** | 1167–1172 / 1467–1471 |
| 控件（按钮 /「＋」珠） | 10 | 24 / 18% | `(61,63,78)` / `(62,64,80)` | edge | 376–383、400–419 |
| 胶囊 / 分组标题 | 8 | 无 | — | 无 | 370–374、1149 |
| 折叠栏 | 16 | 16 / 12% soft | — | drop | 905–910 |

实测峰值与声明 alpha 逐条对得上：16% → 51、24% → 61~65、30% → 74~77（地面 `(16,16,26)`、
`label-primary` = `#cdd6f4`），所以这张表不是「看图的印象」，是可复算的。

## 2. 七条不一致

### ① 设置对话框没有投影 —— 确定性遗漏（源码确认）

`[role='dialog'][aria-modal='true']` 在 mica（1167）与 compat（1467）两处都只写了
`background` / `border` / `box-shadow: var(--dsh-glass-edge)`（内描边光） / `backdrop-filter`，
**没有 `--dsh-glass-drop`**。层级最高的模态（浮在遮罩之上）反而比顶栏、侧栏、输入卡都平。

- 修法：两处都补 `box-shadow: var(--dsh-glass-edge), var(--dsh-glass-drop);`
- 成本：2 行。风险：无（只在 mask 上多一层影）。
- 需真机看：暗色 mask（很暗）+ 深色影是否读得出来；Latte 需另看一次（浅地面上影更明显）。

### ② 容器 rim 比容器内的控件还淡 —— 层级倒挂

同一块侧栏卡里：卡的 rim 是 `rim-soft`（暗 16% / 浅 12%，实测 `(51,52,67)`），里面「新会话」按钮的 rim 是
`--dsh-glass-rim`（暗 24% / 浅 18%，实测 `(61,63,78)`），**按钮比它所在的框更亮**。
按钮的这层 border 来自 `[data-dsh-glass-surface]`（414–419 行），而接缝 `glass-seams.ts:33`
确实把它打在了 `button[class*="newSession"]` 上。输入卡那条是对的（卡 30% → 内部「＋」珠 24%），
说明这不是配方错误，而是没立过「外框 ≥ 内框」这条规则。

- 修法：把「新会话」按钮（`[data-dsh-glass-surface]`）的 border 降到 `--dsh-glass-rim-soft`，
  与卡同档；或反过来给侧栏回 18%（**不建议**：#26 有实测说 Latte 下太实、会被读成贴上去的相框）。
- 成本：1 行。风险：按钮的「主操作」辨识度下降，靠 `card-raised` 填充（64%）撑着。

### ③ 圆角 24 vs 20 —— 语言本身的分歧（源码确认）

输入卡 24（975），顶栏 / 侧栏 / 轨迹都是 20，而且三者与输入卡同列并排、差距一眼可见。
整套语言目前是 24 / 20 / 14 / 10 / 8（+ 折叠栏 16），20 与 24 两个大面档位同时存在。

- 选项 A（推荐，改动最小）：输入卡回 20，大面统一 20。
- 选项 B：四个大面全抬 24（顶栏下面就是正文，24 会吃掉一点标题块的对齐感）。
- ⚠️ **`docs/issue-28-fused-composer-plan.md` 把 24 当作既定前提**（「卡与 dock 共用一个 24px 圆角外框」），
  选 A 必须同步改那份方案；选 B 则不用动。
- 成本：1 行 + 文档同步。

### ④ 顶栏右侧三个控件三种形态（仅截图取证）

同一行里并排：① 分段按钮（文件夹 + chevron）有 1px **中性白**描边 `(66,66,75)`——和皮肤偏蓝的
label rim `(62,64,80)` 不同源，也不是 `--dsh-glass-*` 系列；里面是**未主题化的黄 emoji** `(220,156,0)`，
全窗口唯一的饱和色；② 旁边的「…」无框；③ 最右的面板图标用 stock 白线 `(139,145,168)`，比 rim 亮一倍。

**归属未确认**：本插件对这三个元素只可能命中过圆角规则（`[class*='iconButton']` 8px、
`button[class*='button']` 10px），**没有设过描边、填充或图标色**——那条白框与黄 emoji 都是上游（或第三方插件）画的。
所以这条不是「皮肤画歪了」，而是「皮肤没管它们」；要动先取 DOM 确认归属。

- 修法：统一成「裸图标 + hover 玻璃珠」（与 #22 ③ 的 no-outline 词汇一致），emoji 换 token 着色图标。
- 成本：0.5–1h，**前提是这三个控件有稳定 hook**——没 hook 就只能挂 class 子串，属脆弱选择器，
  得先按 `docs/glass-mis-hits.md` 的方式核一遍再决定做不做。

### ⑤ 左右边不齐（浮起来才暴露；成因在上游布局，不在本表）

实测（CSS px，窗口宽 1706.7）：顶栏左右各 16；输入卡在居中列里，左 69 / 右 75；气泡列是第三个宽度。

| 面 | 左 | 右 |
|---|---|---|
| 顶栏 | 296 | 1691 |
| 输入卡 | 349 | 1632 |
| 气泡 | 1331 | 1615 |

顶栏比输入卡左右各外扩 ≈ 53 / 59px。stock 布局本来如此（顶栏铺满列、输入卡有 max-width），
但皮肤把两者都画成浮起的框之后，这条错位就变成可见的「两个框没对齐」。

- 修法：给三个同列浮面统一一条 inset 变量，或去掉 composer 的 max-width 让它铺满。
- 成本：2–3h + 回归。**属布局改动，不是皮肤层能干净做到的**，建议单独立项而不是顺手改。

### ⑥ 侧栏卡底边留白 5px，其余三边 12px（本表无对应规则，成因未定位）

实测设备像素：左 18 / 上 18 / 下 **8**（CSS ≈ 12 / 12 / 5.3）。上边与顶栏卡对齐（都在 77–78），
只有底边更贴。**本表对 `[class*='sidebarCol']` 声明的是 `margin: 12px`（四边相等，807 行），
所以 5px 不是这张表造成的**——只能来自上游列高（列可能不是 100% 高）或外壳的 frame bottom clearance。
判定前先跑一次 computed style，别照着截图直接改 margin，那会把另外三边一起推。

- 修法：先查原因（打印 sidebarCol 的 computed margin / height 与父级 padding），再决定补不补。
- 成本：1 步排查。

### ⑦ 菜单无框 vs 对话框有框 —— 同级浮层的语言分裂（源码确认）

`#22 ③` 把菜单表面的 1px 框撤了（理由：Latte 下读成实框），但对话框保留 `--dsh-glass-rim`
（暗 24 / 浅 18%），气泡/产物块/turn-trigger 保留 `rim-soft`（暗 16 / 浅 12%）。于是「真浮层（菜单）」裸奔，
「流里的块」有边。

- 修法：只给暗色补回 `--dsh-glass-rim-soft`（`body[data-ds-dark-theme]` 分支），Latte 保持无框。
- 成本：1 条规则 + CDP 验 Latte 逐像素不变（否则就是重犯 #22 ③）。

## 3. 建议收敛成的阶梯

| 层级 | 圆角 | rim（暗 / 浅） | 投影 |
|---|---|---|---|
| 大面（顶栏 / 侧栏 / 轨迹 / 输入卡） | 20 | 16–30 / 12–30%（各有 CDP 证据，不动） | edge + drop |
| 模态对话框 | **20** | 24 / 18% | **edge + drop（补上）** |
| 浮层（菜单 / 气泡 / 产物块 / turn-trigger） | 14 | 16 / 12% soft（暗色菜单补回） | 无 |
| 控件（按钮 / 圆珠） | 10 | **≤ 该容器同档（不得亮于所在容器）** | edge |
| 原子（胶囊 / chip） | 8 | 无 | 无 |

一句话：现在这套唯一真正破格的是 ③ 的 24、① 的没影、② 的倒挂；其余是历史决策，别顺手统一。

## 4. 明确不要动的

- **dock 背板（#28 A）**：实测该带与地面 Δ2/255，肉眼不可见，符合「隐形背板」的设计意图，改它会破坏 #28 的结论。
- **输入卡 30% / 侧栏 16%（暗，浅色 12%）两个 rim 档**：各有 #22-follow-up 与 #26 的实测数字支撑，属于「看起来不统一但都有据」。
- **气泡无 backdrop-filter**（#13 模糊预算）、**菜单无框**（#22 ③ Latte 证据）：重开会推翻已结案的 issue。

## 5. 验证方式（真改了以后）

1. `pnpm typecheck && pnpm typecheck:tests && pnpm build`，再跑 `pnpm vitest run --no-file-parallelism`（336 条基线）。
2. 改动只要落进 `glass-css.spec.ts` 锁过的选择器族（dialog / menu / composer / bubble），补一条护栏断言。
3. 真机 A/B：同一状态截两张（开/关该条），差异只应出现在该框自身，不牵动相邻面。
4. 四个风味 × mica/compat 各看一次 `rim` 与影（Latte 的影最明显，Mocha 的影最容易被吃掉）。
