# 框语言审计：七个「框」对不上的地方（2026-10-19）

- 触发：维护者 2026-10-19 真机截图提问「当前插件有哪些框是不统一、或你觉得需要改的」。
- 状态：**①②③⑦ 已于 2026-10-19 实施**（提交 `27fd88f`；闸门全绿，344 测试）。其中 ③ 只动
  **模态**圆角，**输入卡保持 24 不动**——维护者确认「输入框亮一些」是本意（30% 强描边 + 双层影
  = 主输入面），所以 24 与 30% 都保留。**⑤ 已查清成因**（上游两条定宽规则，3 行可改但属布局改动，
  等维护者拍板）；**⑥ 复核后撤回**（量测错误，四边都是 12px）；**④ 仍只有截图取证**（控件归属未查）。
- 取证环境：官方桌面壳 `0.2.1-rc.2`，Mocha + mica（float），Windows 标题栏在位，截屏 2560×1528，
  设备像素 / CSS px = **1.5**（三点标定，全部逐像素吻合：侧栏左距 12px→18、上距 40+12px→78、
  下距 12px→1528−18=1510；另侧栏列宽 279 ≈ 上游默认 280、顶栏 margin 16→444）。
- 取证方法：逐行扫像素取**描边峰值 RGB** 与圆弧轨迹拟合，再对 CSS 逐条核对。出图
  `.debug/frame-audit/AUDIT_annotated.png`（**不入库**，同目录另有 8 张裁切件）。描边亮度可直接横向比：
  同一 Mocha 地面 `rgb(16,16,26)` 上，alpha 越高峰值越亮。

## 1. 现在的框长什么样

**alpha 有两个口径，别混**（这条 2026-10-19 复核时更正过）：三档 rim 在**浅色**分支是
18 / 12 / 30%（`glass.module.css` 57–59 行），在**暗色**分支是 **24 / 16 / 30%**（111–117 行）——
暗地面上同 alpha 读起来更弱，所以整体抬了一档。下表「rim」列按 `暗 / 浅` 写（截图是 Mocha，取暗色那档）。

| 面 | 圆角 | rim（暗 / 浅） | 峰值 RGB（Mocha） | 投影 | 出处 |
|---|---|---|---|---|---|
| 会话顶栏 | 20 | 24 / 18% | `(65,67,82)` | edge + drop | 759–767 |
| 侧栏卡 | 20 | **16 / 12% soft** | `(51,52,67)` | **只 drop，无 edge** | 799–828（#26 软化） |
| 轨迹面板 | 20 | 24 / 18% | —（本图未开） | edge + drop | 926–935 |
| 输入卡 | **24** | **30 / 30% strong** | `(74,77,93)` | input-shadow 双层 | 973–995（#22 加强） |
| 消息气泡 | 14 | 16 / 12% soft | `(47,49,64)` | 无 | 436–451 |
| 菜单（MenuSurface） | 14 | **0（撤了）** | — | 上游自己的 | 1104–1107（#22 ③） |
| 对话框 | **20（模态）/ 14（小弹层）** | 24 / 18% | —（本图未开） | **edge + drop（2026-10-19 补）** | 1167–1172 / 1467–1471 |
| 控件（按钮 /「＋」珠） | 10 | 24 / 18% | `(61,63,78)` / `(62,64,80)` | edge | 376–383、400–419 |
| 胶囊 / 分组标题 | 8 | 无 | — | 无 | 370–374、1149 |
| 折叠栏 | 16 | 16 / 12% soft | — | drop | 905–910 |

实测峰值与声明 alpha 逐条对得上：16% → 51、24% → 61~65、30% → 74~77（地面 `(16,16,26)`、
`label-primary` = `#cdd6f4`），所以这张表不是「看图的印象」，是可复算的。

## 2. 七条不一致

### ① 设置对话框没有投影 —— 确定性遗漏（源码确认 · 已实施 2026-10-19）

`[role='dialog'][aria-modal='true']` 在 mica（1167）与 compat（1467）两处都只写了
`background` / `border` / `box-shadow: var(--dsh-glass-edge)`（内描边光） / `backdrop-filter`，
**没有 `--dsh-glass-drop`**。层级最高的模态（浮在遮罩之上）反而比顶栏、侧栏、输入卡都平。

- 修法：两处都补 `box-shadow: var(--dsh-glass-edge), var(--dsh-glass-drop);`
- 成本：2 行。风险：无（只在 mask 上多一层影）。
- 需真机看：暗色 mask（很暗）+ 深色影是否读得出来；Latte 需另看一次（浅地面上影更明显）。

### ② 容器 rim 比容器内的控件还淡 —— 层级倒挂（已实施 2026-10-19）

同一块侧栏卡里：卡的 rim 是 `rim-soft`（暗 16% / 浅 12%，实测 `(51,52,67)`），里面「新会话」按钮的 rim 是
`--dsh-glass-rim`（暗 24% / 浅 18%，实测 `(61,63,78)`），**按钮比它所在的框更亮**。
按钮的这层 border 来自 `[data-dsh-glass-surface]`（414–419 行），而接缝 `glass-seams.ts:33`
确实把它打在了 `button[class*="newSession"]` 上。输入卡那条是对的（卡 30% → 内部「＋」珠 24%），
说明这不是配方错误，而是没立过「外框 ≥ 内框」这条规则。

- 修法：把「新会话」按钮（`[data-dsh-glass-surface]`）的 border 降到 `--dsh-glass-rim-soft`，
  与卡同档；或反过来给侧栏回 18%（**不建议**：#26 有实测说 Latte 下太实、会被读成贴上去的相框）。
- 成本：1 行。风险：按钮的「主操作」辨识度下降，靠 `card-raised` 填充（64%）撑着。

### ③ 圆角 24 vs 20 —— 语言本身的分歧（源码确认 · 已实施 2026-10-19）

输入卡 24（975），顶栏 / 侧栏 / 轨迹都是 20，而且三者与输入卡同列并排、差距一眼可见。
整套语言目前是 24 / 20 / 14 / 10 / 8（+ 折叠栏 16），20 与 24 两个大面档位同时存在。

- 选项 A（推荐，改动最小）：输入卡回 20，大面统一 20。
- 选项 B：四个大面全抬 24（顶栏下面就是正文，24 会吃掉一点标题块的对齐感）。
- ⚠️ **`docs/issue-28-fused-composer-plan.md` 把 24 当作既定前提**（「卡与 dock 共用一个 24px 圆角外框」），
  选 A 必须同步改那份方案；选 B 则不用动。
- 成本：1 行 + 文档同步。

### ④ 顶栏右侧三个控件三种形态（仅截图取证）

同一行里并排：① 分段按钮（文件夹 + chevron）有 1px **中性白**描边 `(66,66,75)`——和皮肤偏蓝的
label rim `(62,64,80)` 不同源，也不是 `--dsh-glass-*` 系列；里面是**未主题化的黄 emoji** `(220,156,0)`，
全窗口唯一的饱和色；② 旁边的「…」无框；③ 最右的面板图标用 stock 白线 `(139,145,168)`，比 rim 亮一倍。

**归属未确认**：本插件对这三个元素只可能命中过圆角规则（`[class*='iconButton']` 8px、
`button[class*='button']` 10px），**没有设过描边、填充或图标色**——那条白框与黄 emoji 都是上游（或第三方插件）画的。
所以这条不是「皮肤画歪了」，而是「皮肤没管它们」；要动先取 DOM 确认归属。

- 修法：统一成「裸图标 + hover 玻璃珠」（与 #22 ③ 的 no-outline 词汇一致），emoji 换 token 着色图标。
- 成本：0.5–1h，**前提是这三个控件有稳定 hook**——没 hook 就只能挂 class 子串，属脆弱选择器，
  得先按 `docs/glass-mis-hits.md` 的方式核一遍再决定做不做。

### ⑤ 左右边不齐 —— 上游两条定宽规则（2026-10-19 查清，源码确认）

**成因查到了，不是本表写错，也不是随机数**：上游给顶栏和输入卡**各用了一条宽度规则**，两者互不参照。

| 面 | 宽度规则 | 出处（`dsh-client-ui-conversation/lib/client.js`，0.2.1-rc.2） |
|---|---|---|
| 顶栏 | 整列铺满，两侧各留 16px（本表 `margin: 12px 16px 0`） | `glass.module.css` 760 |
| 输入卡 | `max-width: var(--dsh-composer-card-max-width)`，居中 | `uV2eYG_card` |
| 而 | `--dsh-composer-card-max-width: calc(var(--dsh-chat-content-width) + 32px)` | `wSkVaW_body` |
| 而 | `--dsh-chat-content-width: var(--dsh-chat-user-width, clamp(680px, 列宽 × .64, 920px))` | 同上 |

`--dsh-chat-user-width` 是**正文列宽度手柄**写进内联样式的值，且**有上限**：

```js
resolveContentWidth(column, preference) {
  max = Math.max(CONTENT_MIN, column - CONTENT_EDGE_BUDGET);  // EDGE_BUDGET = 176
  return preference ? clamp(preference, CONTENT_MIN, max)
                    : Math.max(680, Math.min(column * .64, 920));
}
```

实测（列宽 1427.3）：正文列 1251.3 = **1427.3 − 176**，即手柄已拖到上限；输入卡 1283 = 1251 + 32；
顶栏 1395 = 1427 − 32。**每侧差 56px**（实测左 79 / 右 89 设备像素 = 53 / 59 CSS，那 6px 的左右
不对称来自 `scrollBody` 的 `scrollbar-gutter: stable`——卡在滚动容器里，顶栏不在）。

⚠️ 反直觉的一点：**不拖反而更不齐**。默认（无手柄偏好）正文列 = min(0.64 × 列宽, 920) =
913 → 卡 945，每侧差 **225px**。是「拖到最大」把差距从 225 缩到 56。

**能改，也是泛用的**（3 行，热跟随手柄）——但它是**布局改动**，会让顶栏卡变窄、标题与标签往里缩：

```css
[data-dsh-glass-float] [data-phase] header:not([class*='headerBlank']) {
  max-width: var(--dsh-composer-card-max-width, none);
  margin-inline: auto;
}
```

- 兜底：`var(..., none)` ⇒ 老宿主（该变量不存在时）退回**今天的满宽观感**，不会坏。
- 该变量在 0.2.0-rc.2 与 0.2.1-rc.2 都存在（各 5 处）；**0.1.7 未验证**，靠上面的兜底。
- 需要同时处理折叠栏那条 `margin-left: 28px`（否则折叠时左对齐、不居中）。
- **未实施，等维护者点头**：这不是「皮肤画歪了」，是上游「顶栏是 chrome、正文是阅读列」的
  设计被浮框暴露出来；对齐等于把顶栏降级成「在阅读列里的卡」。

### ⑥ 侧栏卡底边留白 —— **撤回，是量测错误**（2026-10-19 复核）

原来记的是「左 18 / 上 18 / 下 8 设备像素」。**8 是错的**：当时把窗口底部那条 8px 的亮边
（Windows 窗口边缘，不是页面内容）当成了内容边界。用三个已知量做标定后，底边其实是满的：

| 已知量 | 期望（设备像素） | 实测 |
|---|---|---|
| 侧栏左外边距 12px | 18 | 18 |
| 上边距 = 标题栏 40 + 12 = 52px | 78 | **78** |
| 下边距 12px（窗口高 1528） | 1528 − 18 = 1510 | **1510** |

三处全部逐像素吻合（标定比 = 1.5 设备像素/CSS px），所以**四边都是 12px，没有问题**。
卡片下缘外面那 8px 暗带是 `--dsh-glass-drop` 的投影，不是「更贴边」。
**不做任何改动**——按截图去补 bottom margin 反而会把另外三边一起推下去。

### ⑦ 菜单无框 vs 对话框有框 —— 同级浮层的语言分裂（源码确认 · 已实施 2026-10-19）

`#22 ③` 把菜单表面的 1px 框撤了（理由：Latte 下读成实框），但对话框保留 `--dsh-glass-rim`
（暗 24 / 浅 18%），气泡/产物块/turn-trigger 保留 `rim-soft`（暗 16 / 浅 12%）。于是「真浮层（菜单）」裸奔，
「流里的块」有边。

- 修法：只给暗色补回 `--dsh-glass-rim-soft`（`body[data-ds-dark-theme]` 分支），Latte 保持无框。
- 成本：1 条规则 + CDP 验 Latte 逐像素不变（否则就是重犯 #22 ③）。

## 3. 建议收敛成的阶梯

| 层级 | 圆角 | rim（暗 / 浅） | 投影 |
|---|---|---|---|
| 大面（顶栏 / 侧栏 / 轨迹 / 输入卡） | 20 | 16–30 / 12–30%（各有 CDP 证据，不动） | edge + drop |
| 模态对话框 | **20** | 24 / 18% | **edge + drop（补上）** |
| 浮层（菜单 / 气泡 / 产物块 / turn-trigger） | 14 | 16 / 12% soft（暗色菜单补回） | 无 |
| 控件（按钮 / 圆珠） | 10 | **≤ 该容器同档（不得亮于所在容器）** | edge |
| 原子（胶囊 / chip） | 8 | 无 | 无 |

一句话：①②③⑦ 已收口，剩下的 24（输入卡）是维护者确认的「主输入面亮一档」，属有意为之，不是破格。

## 4. 明确不要动的

- **dock 背板（#28 A）**：实测该带与地面 Δ2/255，肉眼不可见，符合「隐形背板」的设计意图，改它会破坏 #28 的结论。
- **输入卡 30% / 侧栏 16%（暗，浅色 12%）两个 rim 档**：各有 #22-follow-up 与 #26 的实测数字支撑，属于「看起来不统一但都有据」。
- **气泡无 backdrop-filter**（#13 模糊预算）、**菜单无框**（#22 ③ Latte 证据）：重开会推翻已结案的 issue。

## 5. 验证方式（真改了以后）

1. `pnpm typecheck && pnpm typecheck:tests && pnpm build`，再跑 `pnpm vitest run --no-file-parallelism`（基线已到 **344** 条）。
2. 改动只要落进 `glass-css.spec.ts` 锁过的选择器族（dialog / menu / composer / bubble），补一条护栏断言。
3. 真机 A/B：同一状态截两张（开/关该条），差异只应出现在该框自身，不牵动相邻面。
4. 四个风味 × mica/compat 各看一次 `rim` 与影（Latte 的影最明显，Mocha 的影最容易被吃掉）。

## 6. 实施记录（2026-10-19，提交 `27fd88f`）

| 条 | 改了什么 | 位置 |
|---|---|---|
| ① | mica 与 compat 的模态都补 `var(--dsh-glass-drop)`（与 edge 并列） | `glass.module.css` 对话框两处 |
| ③ | 模态 `border-radius: 20px`；**只限 `aria-modal='true'`**，通用 `[role='dialog']` 仍 14 | 同上 |
| ② | `[data-dsh-glass-surface]` 的 border 从 `--dsh-glass-rim` 降到 `--dsh-glass-rim-soft` | 新会话按钮座位 |
| ⑦ | 新增 `body[data-ds-dark-theme] [data-menu-material='translucent']:not(:focus-visible) { outline: 1px solid var(--dsh-glass-rim-soft); outline-offset: -1px }` | 菜单座位之后 |

护栏（`tests/glass-css.spec.ts` → `frame language: one rim ladder, one shadow language`）：

1. 两个模式的模态都必须带 edge **和** drop；
2. 模态在 20px 档、通用 dialog 仍在 14px 档（防「一刀切把弹层也抬高」）；
3. `[data-dsh-glass-surface]` 的 border 只能是 soft，且**必须存在**（防止反向退化成无框）；
4. 暗色菜单必须有一条 soft outline + `-1px` offset。同时原来的 `menuSeat` 守卫从「一律不许描边」
   放宽为「**只有暗色分支许描边，且必须是 soft**」——第 3 轮 Latte 的证据继续有效。

闸门：`pnpm typecheck` / `pnpm typecheck:tests` / `pnpm build` 全绿，
`vitest run --no-file-parallelism` → **344 passed（20 files）**。

**真机未验**（本机 Playwright 不可用）：四风味 × mica/compat 的观感确认待补。重点看三处——
Latte 的菜单是否仍完全无框（逐像素应不变）、Mocha 的菜单描边在密集正文上会不会过重、
Latte 的模态投影会不会显脏。

遗留：**④ 顶栏右侧三控件**（要先取 DOM 确认归属）；**⑤ 左右边不齐**（成因已查清：上游顶栏走
「列 − 32」、输入卡走「正文列 + 32」，补丁 3 行、有 `var(..., none)` 兜底，但会改顶栏宽度
——等维护者点头）；**⑥ 已撤回**（四边都是 12px，量测错误）。
